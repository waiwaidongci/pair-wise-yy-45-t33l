# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + RTK Query + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 版型结论链（量体 / 认可 / 冻结 / 并发 / 升级）

- **量体改动驱动**：每个轮次的量体数字带版本号（v1、v2…）。任一部位实测值修改即升版，依据旧数字的改版认可全部置为「已失效」、采纳状态打回待决定，新结论按新数字当场重算超差部位。
- **冻结版只读**：审核冻结时生成不可变快照（含当时量体版本与超差清单）；解锁后的量体与方案调整另存「冻结后调整」新结论，冻结版永不被改写。
- **先到成立的并发确认**：提交结论需携带保存版本（乐观锁）。版师与产品同时确认同一款时，第一笔落库成立，第二笔被拦截并弹出「两次保存差异」对比；只能放弃，或另存为「并行确认」结论，均不覆盖对方。
- **旧数据兼容升级**：结论数据带 `schemaVersion`。v1 记录自动升级并保留原字段；读不到版本号或内容损坏时，原记录原样保全到 recovery 键（可下载、可重试升级），应用以默认数据继续运行。
